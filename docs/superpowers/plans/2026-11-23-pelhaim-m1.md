# pelhaim M1 (Observe + board + alerts) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust desktop app, `pelhaim`, that read-only observes every Claude Code and Codex session on this Mac and draws them as a matte subway track board. Agents are placed on project lines by `pelhaim-project:` tags, with DISPATCH and Unsorted lines. Questions surface as alert popups with a tray. One click logs a decision to SQLite and exports it to `~/Developer/DECISION-LOG.md`. The Mac stays awake while agents work.

**Architecture:** Observe adapters turn the session files into `Event`s. A pure, synchronous `Engine` (no IO, injected time) folds `Input`s into state and returns `Effect`s. A pure board layer builds `(Snapshot, ViewState) → Scene` (display list plus hit map). A wgpu renderer draws the display list in a winit window. A thin binary runs the engine on a tokio task, executes effects (SQLite store worker, decision-log export, caffeinate holder), and implements the `RemoteApi` seam the local UI answers through.

**Tech Stack:** Rust 1.100.0 (edition 2024), tokio, notify, serde/serde_json/toml, rusqlite (bundled), chrono, clap, winit, wgpu, accesskit + accesskit_winit, unicode-segmentation, arboard, tracing, sha2. Tests: insta (ron), proptest, tempfile, png (goldens only).

**Spec:** `docs/superpowers/specs/2026-11-23-pelhaim-design.md` (commit 2e3b957). §5.1, §5.2 and §16 override earlier sections. M1 scope is §13 "M1". Visual reference (private, never copied into the repo): `~/Developer/pelhaim-reference/VISUAL-SPEC.md` and the spike `~/Developer/pelhaim-spike/src/main.rs`.

## Review Focus

1. **A parent session waiting on a long-running subagent or command.** Its `Agent` call stays open for many minutes while its own JSONL is silent. The owner expects the train to stay green (working), not turn "probably waiting on you" or "stalled". Writes to a session's live subagent files count as that session's activity, and open `Agent`/`Task` calls never trigger the permission heuristic. Pinned in Task 4.
2. **Non-ASCII and control characters in prompts, questions and labels** (emoji, CJK, smart quotes, ANSI escapes, a tag line at the top). The board must never panic on a byte-slice boundary, must truncate by characters, must not show the `pelhaim-project:` line as the station title, and must draw unknown glyphs as a fixed-width box. Pinned in Tasks 2 and 13.
3. **A session file that is truncated, replaced or deleted while tailed, or a record with no `timestamp`.** The train must rebuild without duplicate stations or alerts, and its alerts must expire when the file goes. Pinned in Tasks 3, 8 and 9.
4. **DECISION-LOG.md as it really is:** headings with suffixes (`## pelhaim (new, 2026-11-23)`, `## mlb fan sentiment ("mlballpark")`), CRLF endings, no trailing newline, a symlinked path, a section with no `### Decided`. The entry must land in the existing section, never a duplicate one, and every other byte must be preserved. Pinned in Task 7.
5. **First run with no config file and dozens of untagged historical sessions.** The board must still open on defaults, show at most one popup, queue the rest in the tray with a count, and never steal keyboard focus from the console when a popup auto-opens. Pinned in Tasks 5 and 16.

**Rules this task implements** (§7.2–§7.4, §7.7, §8.1):

- **Line resolution order:** owner assignment, then the spawn-prompt tag (subagents), then the self tag, then Unsorted.
  - A session id listed in `dispatch_sessions`, or `Tagged("dispatch")`, goes to `LineKey::Dispatch`.
  - A well-formed slug not in config is `MisTagged` and goes to Unsorted.
  - A subagent never inherits its parent's tag.
  - **cwd never affects the line.**
- **Lines in a Snapshot**, in order: `Dispatch` always first; then every configured project by `order` (when `float_alert_lines`, lines with `has_open_alert` move up and keep their relative order); `Unsorted` always last. All lines are always present; `active = !tracks.is_empty()`.
- **Track order within a line:** has an open alert first, then `Working`, then `last_activity` descending.
- **A train per session:**
  - `number` comes from `started` in `local_offset`;
  - `label` is the `TitleChanged` title, else the subagent description, else `"<tool> session"`;
  - the initial state is `Idle` with `Position { leg: 0, block: 0, berthed: false }`;
  - a subagent starts `Working` with one station titled with its description.
- **Movement:**
  - `PromptStarted` appends a station (main sessions only), sets the train `Working`, and moves it to `Position { leg: index of the new station, block: 0, berthed: false }`. The previous station becomes `Done`.
  - `ToolOpened` adds one block, capped at `LEG_BLOCKS - 2`; the train never passes an unfinished station. It also increments `tool_calls`.
  - `TurnEnded` sets `block = LEG_BLOCKS - 1, berthed = true`, makes the station `Done`, sets the state to `Idle` (`Done` for subagents), and increments `turns`.
  - A `ToolOpened` after a `TurnEnded` with no new prompt reopens the station (`Active`, `berthed = false`, block `LEG_BLOCKS - 2`).
- **Subagent finish:** `ToolClosed { launched_only: false }` on the parent for the `tool_use_id` that spawned a subagent, or `SubagentFinished`, makes the child `Done` and berthed.
  - **Background subagents** (fix round 1, 2026-11-23): a `ToolClosed { launched_only: true }` is only the launch acknowledgement. It never finishes the child; the child's own lifecycle (`TurnEnded`, `SubagentFinished`, `SessionGone`) does.
  - A main session whose turn has ended (berthed) stays `Working` while any child train is not `Done`, and goes `Idle` when the last one finishes. `effective_last_write` includes those children.
- **Forks:**
  - `SpawnRequested` records the parent train's position.
  - When the child is known (by `SubagentLinked`, in either arrival order), it creates `Fork { parent_track, at: that position, child_track }` and resolves the child's line from the spawn tag.
- **Failures:** `Failed` sets `Failed(reason)`; the next `ToolOpened`, `PromptStarted` or `WorkStarted` returns the train to `Working`.
- **Reset and removal:**
  - `SessionReset` clears that session's stations, forks, open calls and derived alerts, but keeps its `TrainId`, number and owner assignment.
  - `SessionGone` removes the train, its track and its forks, and expires its alerts.
- **Activity:** every event with an `at` updates `counters.last_seen` and the track's `last_activity`.

| Alert | Id |
|---|---|
| Question | `q:<session_key>:<call_id>` |
| Assign | `assign:<session_key>` |
| Stalled | `stalled:<session_key>:<station_index>` |
| Result | `result:<session_key>:<turns>` |

**Rules:**

- **Questions:**
  - `QuestionAsked` → `Question` alert, `answerable = false` (observed), and the train goes to `Waiting(id)`.
  - `QuestionAnswered` → `Answered { answer, by: Terminal }`, `AlertEvent::Answered`, and the train goes back to `Working`.
- **The permission heuristic**, evaluated on `Tick(now)` (§8.1):
  - The train goes to `ProbablyWaiting` when it is `Working` and the following all hold:
    - an open call, excluding `AskUserQuestion`, `Agent` and `Task`, opened at or before `now - permission_after`;
    - `effective_last_write <= now - permission_after`, where `effective_last_write` is the max of the session's `last_seen` and the `last_seen` of its non-Done child subagent trains.
  - There is no alert; the inset label reads "probably waiting on you in the terminal".
- **The stall heuristic:**
  - A train that is `Working` or `ProbablyWaiting` with `effective_last_write <= now - stall_after` goes to `Stalled`.
  - It raises a `Stalled` alert whose body reads `Trying to contact train <number>…`.
  - Any later event for the session restores `Working` and makes that alert `Expired`.
- **Assign alerts:** a train resolving to Unsorted with `Untagged` or `MisTagged` raises `AssignProject`.
  - Options are the projects in config order, then `AssignOption { label: "This is the orchestrator", target: Dispatch }`.
  - `prefill` is `closest_slug(raw)` for MisTagged, else `None`.
- **Result alerts:** only when `cfg.result_alerts`. `TurnEnded` with `final_text` raises one, with `truncate_chars(final_text, 600)`.
- **Answering:** `answer()` checks, in order:
  1. Unknown id → `UnknownAlert`.
  2. Already `Answered` → `AlreadyAnswered`.
  3. `!answerable` → `NotAnswerable`.
  4. Remote origin with `!kind.remote_answerable()` → `ViewOnlyFromRemote`.
  5. Choice validity: AssignProject takes exactly one in-range option, else `InvalidChoice`.

  On success it performs the assignment: `Persist(Answered)`, `Persist(Assigned)`, then `Answered { by: Local | Remote }`, and the train moves line. The first answer wins.
- **What an assignment applies to** (`Command::Assign` or the answer):
  - the session's train;
  - each of its subagents whose tag is `Untagged` and whose `started >= assignment time`, including ones discovered later;
  - it never overrides a tagged subagent.
- **Dismiss and reopen:**
  - `Dismiss` turns Open into Tray and emits `Persist(Dismissed)`. On an Answered alert it is a no-op (`Ok`, no persist).
  - `Reopen` turns Tray into Open and emits `Persist(Reopened)`.
  - A re-derived alert whose id is in the in-memory tray set starts as `Tray`.
- **`LogDecision`:**
  - It requires an Answered alert.
  - Project: the given `project`, else the train's line slug. Dispatch or Unsorted with no project → `NeedsProject`.
  - Question alerts: title = `"<header>: <answer>"`, using the first question's header, or `truncate_chars(question, 60)` if the header is empty; why = all question texts joined by `"; "`. Assign alerts: title = `"Session <first 8 of session_id> assigned to <target name>"`, why = `"Untagged session placed by the owner"`.
  - who = `Owner`; origin = `Local`; date = `now` in `local_offset`.
  - The id is `max(existing) + 1`.
  - Effects: `Persist(DecisionLogged)`, plus `ExportDecision` if `decision_log_write`.
  - `ExportPending` re-emits `ExportDecision` for each row with `written_to_md == false`.
  - `DecisionExported` sets `written_to_md` and emits `Persist(DecisionExported)`.
  - `DecisionExportFailed` raises `Failure { reason: "Decision log not written: <reason>" }`.
- **Keep-awake** (§8.6):
  - `count` = the number of trains `Working`, if `include_observed`, plus the trains `Waiting` or `ProbablyWaiting` if `remote_enabled`.
  - On 0 → ≥1, with the feature enabled and not paused: `Hold`.
  - When the count drops to 0: `Release` is emitted on the first Tick at or after 60 s; it is cancelled if the count rises again.
  - `PauseKeepAwake { until }`: `Release` now (if held); then `Hold` on the first Tick at or after `until` if `count > 0`.
- **Open-decision counts:** `OpenDecisionCounts` fills `LineView.open_decisions`.
- **Snapshot alerts:** `Snapshot.alerts` lists non-Expired alerts in `created` order.

**Files:**

- Test: `crates/pelhaim-store/tests/decision_log.rs`, goldens in `crates/pelhaim-store/tests/goldens/*.md` (synthetic, shaped like the real file)

**Interfaces:**
- Consumes: `pelhaim_core::{Decision, Who}`.
- Produces:
  - `pub struct LogProject { slug: String, name: String, section_key: String }`, where `section_key` is `log_section`, else `name`;
  - `pub fn render_entry(d: &Decision, eol: &str) -> String`;
  - `pub fn insert_entry(doc: &str, p: &LogProject, entry: &str) -> String` (pure);
  - `pub fn write_decision(path: &Path, p: &LogProject, d: &Decision) -> Result<(), LogError>`;
  - `pub(crate) fn write_decision_with_hook(path, p, d, before_rename: &mut dyn FnMut(&Path)) -> Result<(), LogError>`;
  - `pub fn open_decisions(doc: &str, ps: &[LogProject]) -> BTreeMap<String /*slug*/, Vec<String>>`;
  - `pub enum LogError { NotFound(PathBuf), Conflict, Io(String) }`.

**Format (exact)**, from the file's own rules (§7.6). `render_entry` gives:

```
- **<YYYY-MM-DD>: <title>**
  - Why: <why>
  - Who: <who.as_log_str()>.

```

That is a bullet, two sub-bullets, then one blank line, with every line ending in `eol`. Sanitize `title` and `why` with `sanitize_line`, so a value can't break the list.

**Section matching:** a line `## <heading>` matches `section_key` when the lowercased heading equals the lowercased key, or starts with the key followed by `" ("` or `" "`. The first match wins.

**Insertion:**

- **The section has `### Decided`:** the entry goes after that heading line and the blank lines that follow it, before the first existing entry.
- **The section has no `### Decided`:** insert `### Decided<eol><eol>` plus the entry right before the section's end. The end is the next line starting with `## ` or the next `---` line, whichever comes first; failing both, it is the end of the file.
- **No section matches:** insert `## <name><eol><eol>### Open decisions (need you)<eol><eol>### Decided<eol><eol><entry>` before the line `## Standing rules`, or at the end of the file if there is none.
- **Line endings:** `eol` is `"\r\n"` if the doc contains `"\r\n"`, else `"\n"`.
- **Never** change any byte outside the inserted text. In particular, never touch the `Contents:` line, and never repair a malformed section.

**Safe write:**

1. Canonicalize `path`, following symlinks so the link is preserved. A missing file → `NotFound`; it is never created.
2. Read it and take the sha256.
3. Build the new content.
4. Write `.<file>.pelhaim-tmp-<pid>` in the same dir.
5. Copy the current file to `<file>.pelhaim-bak`.
6. Call `before_rename` (tests only).
7. Re-read and re-hash. If the hash differs, delete the temp file and retry from step 2 once. A second mismatch → `Conflict`.
8. `rename` the temp file over the target.

**Open decisions:** the top-level `- ` bullets directly under that section's `### Open decisions (need you)`, until the next `### ` or `## ` heading. Each is returned as its first line, trimmed.

**Files:**

**Interfaces:**

- Produces:

  - `mod.rs`:
    - `pub enum Cut { C5x7, C7x9 }`;
    - `pub fn fold(c: char) -> char`, which maps `‘ ’` → `'`, `“ ”` → `"`, `– —` → `-`, NBSP → space and `×` → `x`, and keeps other chars;
    - `pub fn advance(cut: Cut, px: f32) -> f32`, which is `(cell_w + 1) * px`;
    - `pub fn line_height(cut: Cut, px: f32) -> f32`, which is 10·px for 5×7 and 12·px for 7×9;
    - `pub fn text_width(s: &str, cut: Cut, px: f32) -> f32`, counting chars;
    - `pub fn draw_text(dl: &mut DisplayList, v: &View, s: &str, x: f32, top: f32, cut: Cut, px: f32, color: Rgba)`.

**Source format** (`glyphs.txt`, original work, MIT): a section header `[5x7]` or `[7x9]`, then per glyph a line `char U+XXXX` and exactly `h` rows of `w` chars, `#` on and `.` off. Lines starting with `# ` (hash, space) at column 0 outside a grid are comments. `build.rs` parses it and writes `OUT_DIR/glyphs.rs` with `static CUT_5X7: &[(char, [u16; 7])]` and `CUT_7X9: &[(char, [u16; 9])]`. It fails the build on a wrong width or height, a duplicate char, or a missing cut. `cargo:rerun-if-changed=../../assets/font/glyphs.txt`.

**Coverage:** every ASCII char `U+0020`–`U+007E`, plus `▶ ◀ ▸ ☐ ☑ ✓ ✕ ⚠ ● · …`, in both cuts. Style (VISUAL-SPEC §5): squarish rounded bowls (corner pixels off on O, 0, D, C and the like), uniform 1-px stroke, mixed case. The glyphs are drawn fresh, never traced.

**The hooked "1" (exact, §5 / VISUAL-SPEC §5: foot to the right):**

```
[5x7] char U+0031      [7x9] char U+0031
.##..                  ..##...
..#..                  ...#...
..#..                  ...#...
..#..                  ...#...
..#..                  ...#...
..#..                  ...#...
..###                  ...#...
                       ...#...
                       ...####
```

**Drawing:**

- `draw_text` emits `Prim::Rect { aa: false }`, merging horizontal runs of on-pixels in a row into one rect.
- Unknown chars (after `fold`) draw a hollow box: the cell's outline, one pixel thick. It has the same advance as any other glyph.
- Coordinates go through `v`, so glyphs scale with `k` (the inset stays crisp, §9.1).

**Files:**

**Interfaces:**
- Consumes: Task 12 `DisplayList`, `Prim`, `Rgba`; Tasks 14–15 `build_scene` (the goldens only).
- Produces:
  - `tessellate.rs`: `#[repr(C)] #[derive(Pod, Zeroable, Clone, Copy)] pub struct Vertex { pos: [f32; 2], color: [f32; 4] /* linear, premultiplied */, local: [f32; 2], half: [f32; 2], aa: f32 }`, `pub struct Batch { scissor: Option<[u32; 4]>, range: Range<u32> }` and `pub fn tessellate(dl: &DisplayList, scale: f32, viewport_px: (u32, u32)) -> (Vec<Vertex>, Vec<u32>, Vec<Batch>)`.
  - `renderer.rs`: `pub struct Renderer`, with `pub fn new(device: &wgpu::Device, format: wgpu::TextureFormat) -> Renderer` and `pub fn render(&mut self, device: &wgpu::Device, queue: &wgpu::Queue, target: &wgpu::TextureView, dl: &DisplayList, viewport_px: (u32, u32), scale: f32, clear: Rgba)`.
  - `offscreen.rs`: `pub fn render_offscreen(dl: &DisplayList, w: u32, h: u32, scale: f32, clear: Rgba) -> anyhow::Result<Vec<u8> /* RGBA8 sRGB */>` (it uses `pollster`) and `pub fn adapter_info() -> Option<String>` (name and backend).

**Rules:**

- **Rect, aa:** a quad grown by 1 device px, with `half` = the half-size and `local` = the position relative to the centre. The fragment's coverage is `clamp(0.5 - sd_box(local, half) / fwidth(local.x), 0, 1)`, which gives square ends and AA edges (§9.1).
- **Rect, not aa:** snapped, `x0 = round(x·scale)`, `x1 = max(x0 + 1, round((x + w)·scale))` (likewise y), `aa = 0`. Glyphs stay sharp.
- **Seg:** an oriented box of length `|b - a| + width` (square caps) and thickness `width`, using the same SDF.
- **Tri:** drawn without the SDF (`aa = 0`). The pass uses 4× MSAA for triangle edges.
- **Clip:** starts a new batch with a scissor, in device px clamped to the viewport. `Unclip` ends it.
- **Colour:** sRGB to linear on the CPU, so a `*Srgb` target shows the exact hex.
