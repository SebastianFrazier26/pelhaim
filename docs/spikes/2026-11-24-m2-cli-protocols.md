## Owner decisions (stop point)

1. **Claude auto default and escalations (S2/S4).** Auto mode lets GET `curl`, writes outside the worktree and `git remote add` through, so the `ask` defaults for `network` and `outside_worktree` are not enforced. The options:
   - **(a)** Keep `auto` + `--permission-prompts none` and accept the gap (R17), relying on post-step checks.
   - **(b)** Also hard-deny network tools via `--disallowedTools` when `network != allow` (e.g. `Bash(curl *)`, `Bash(wget *)`, `Bash(ssh *)`, `Bash(scp *)`, `Bash(git fetch *)`, `Bash(git pull *)`, `WebFetch`). This turns "ask" into "deny". It is a pattern list, not a sandbox.
   - **(c)** Use `auto` + `--permission-prompt-tool stdio`, so whatever auto *does* escalate becomes an alert. Unverified: I could not provoke an escalation. It also exposes `AskUserQuestion` unless that is disallowed.

   My recommendation, a guess: (b) + (c). Adopting (c) means using a flag that is hidden from the `--help` option list.
2. **"ask" mapping (S2):** `--permission-mode manual --permission-prompt-tool stdio` (amended in Task 4). Is the hidden flag acceptable?
3. **Codex resume approval posture (S12):** pass `-c approvals_reviewer="auto_review"`, which works but whose docs are unverified, or let resumes run with `approval_policy = never`? The sandbox still applies either way.
4. **Interrupt (S9):** make `TrainHandle::interrupt()` use the in-band `interrupt` control request (the session survives), with SIGINT as the hard stop?
5. **`--strict-mcp-config` (S5):** adopt it for train sessions? Train sessions would no longer load the owner's MCP servers and connectors. It is cheaper.

## Other notes for later tasks

- **Account:** every Claude run reported `rate_limit_event` `seven_day` utilization **0.98** (`allowed_warning`, overage rejected). Launch-mode trains may hit the weekly limit soon.
- **Codex delegation:** the owner's global `~/.codex/AGENTS.md` makes Codex spawn sub-agents (`spawn_agent`/`wait_agent`). Their tool items never reach the parent's `--json`; only `collab_tool_call` items do (`codex/delegated.jsonl`). In "code mode", one `exec` custom tool can run several commands, and only some of them surface as `command_execution` items. Tool-activity counts from `--json` are therefore a lower bound.
- **Claude hooks:** user hooks fire in `-p` sessions (`hook_started`/`hook_response` lines; one hook blocked a standalone `sleep 30`). Fixtures keep the lines with names and output scrubbed.
- **Planner cost:** about $0.2–0.3 per plan in plan mode (Sonnet), even for trivial plans.
